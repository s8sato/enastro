# ADR-0012: v0.2 Performance Reference Environment and Benchmark Methodology

## Status

PROPOSED

## Context

[07-performance.md](../spec/07-performance.md) は v0.1 時点で REQ-PERF-001（10,000 nodes / 50,000 edges
規模の性能目標）を DEFERRED / OPEN のまま残し、reference hardware / browser / percentile の確定を
Graph UI 着手ループの冒頭で行うとしていた。v0.2 で Graph UI に着手するため、ここで確定する。

ユーザーは具体的な値の提案を agent に委ねた。

## Decision

- **データセット**: [fixtures/benchmark-vault](../fixtures/benchmark-vault) に、決定的（固定シード）な
  手続き的生成スクリプトで 10,000 nodes / 50,000 edges を生成する。
- **計測環境**: Playwright 駆動の headless Chromium（最新安定版）を、本リポジトリの GitHub Actions CI
  （`ubuntu-latest` runner）上で実行する。実機・実ブラウザでの体感性能を保証するものではなく、
  「誰でも同じ手順で再現できる固定ベースライン」として位置づける。
- **統計量**: 連続 10 回計測した上で、中央値（p50）を代表値として報告し、CI のノイズを踏まえて
  最大値（worst-case）も併記する。p95/p99 は試行回数が少なく統計的意味が薄いため v0.2 では採用しない。
- **"first interactive frame" の操作的定義**: `graph.html` のスクリプト実行開始から、build 時に
  事前計算済みのレイアウト座標（[ADR-0006](ADR-0006-graph-layout-precomputation-strategy.md)）が
  最初に画面に描画された直後の最初の `requestAnimationFrame` コールバックまでの時間とする。
  レイアウトは事前計算済みのため、実行時の物理演算収束までは待たない。
- **採用する目標値**: [07-performance.md](../spec/07-performance.md) §2 に記録されていた暫定目標を、
  v0.2 の正式な目標として採用する。
  - first interactive frame ≤ 1,000ms（上記の操作的定義に基づく、p50）
  - tag filter 応答 ≤ 100ms
  - pan/zoom 操作時のフレームレート ≥ 60 FPS（sampled）。ただし headless CI での FPS 計測の限界を
    踏まえ、これは build を失敗させる gate にはせず、実測値をレポートとして残す（性能未達を理由に
    機能・node/edge を省略しない、LOOP.md 安全策 3）。
- 性能目標を満たせない場合でも、達成のために node/edge や機能を黙って間引いてはならない
  （LOOP.md 安全策 3 を継続適用）。未達はユーザーへ報告し、最適化方針は別ループで扱う。

検討した代替案:

- 実機ベンチマーク（開発者のノート PC 等）: 再現性がユーザー環境に依存し、CI で自動検証できない。
- p95/p99 の採用: 試行回数を大幅に増やす必要があり（数十〜百回オーダー）、v0.2 のコストに見合わないため
  見送り、必要になれば将来 ADR で見直す。

## Consequences

- REQ-PERF-001 を v0.2 で DECIDED とし、[07-performance.md](../spec/07-performance.md) の該当箇所を
  OPEN から DECIDED に更新する。
- perf harness（Playwright ベース）の新規実装が必要になる。
- CI 実行環境のハードウェア変動（GitHub Actions runner のスペックは公称されるが可変）により、
  絶対値の比較可能性には限界がある前提を明記しておく。
